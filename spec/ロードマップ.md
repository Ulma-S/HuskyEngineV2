# HuskyEngineV2 ロードマップ(2026-11-14 時点の案)

シーンの切り替え(SC-1〜5)まで終わった時点で、これから作るものを、実装する順に並べた。
**先にやるものほど細かく**(1ステップ = 30分〜1時間の目安、ID 付き)、後のものは大きな区切りと「決めること」だけを書いた。
各段の前に、いつもどおり計画を見せて了承をもらってから始める。依存ライブラリを足すところは ★ を付けた(その段の前に相談する)。

## P0 積み残しの片付け(すぐ。1〜2 セッション)

| ID | 内容 | なぜ |
| --- | --- | --- |
| P0-1 | **ゲームを操作して確かめる道具を直す**。2026-11-14 に、mouse_event のクリックが Play に届かなくなった(前は届いた)。原因を調べ、だめなら開発ビルドだけの起動の引数(`--play`、`--exec "コマンド"`)でコマンドを流せるようにする | 目で確かめる手段が無いと、エディタやゲームの変更の確認がテストだけになる |

| P0-6 | CI(GitHub Actions の Windows で Debug / Release のビルドとテスト) | 手元で回し忘れても気づける。★ 外のサービスを使うので相談 |

## P1 入力の仕上げ(ゲームパッドと入力のアクション)

今の入力: キーボードとマウス(`platform::InputEvents` → `engine::Input`)。ゲームパッドは無い。

決めること(段の最初に相談): ゲームパッドの番号の振り方(つないだ順 / プレイヤーの席)、アクションの定義をアセット(.sdata)にするか。

| ID | 内容 |
| --- | --- |
| IN-1 | **ゲームパッドの入力**: platform で SDL の gamepad のイベント(つなぐ・外す、ボタン、スティック、トリガー)を自前の型(`platform::GamepadEvent`)に写す。SDL の型は platform の外に出さない。`engine::Input` に `IsPadDown(pad, button)` / `WasPadPressed` / `GetPadAxis(pad, axis)`、デッドゾーン(既定 0.15 くらい)。テストはイベントを手で埋める |
| IN-2 | **振動**(`Input::Rumble(pad, 強さ, 秒)`。platform の窓口の後ろで SDL を呼ぶ)と、つながっているパッドの一覧・名前。ImGui がパッドを使っている間は渡さない |
| IN-3 | **入力のアクション**: 「Jump」「Move」のような名前に、キー・マウス・パッドを結びつける表(`InputActionMap`、ScriptableData の .sdata)。`Input::GetAction("Jump")`(押した・離した)と `GetAxis2D("Move")`(WASD とスティックを同じ値に)。ゲームのコードはキーを直接読まない形へ |
| IN-4 | ゲームの例をアクションに移す(プレイヤーの移動をパッドでも)。UI のボタンをパッド・キーで選べるようにする(フォーカスの移動。UI-6 の続き) |
| IN-5 | (後で)キーの割り当ての変更を設定に保存(P2 の後)、文字の入力(IME。UI の入力欄を作るとき) |

## P2 セーブデータと設定

シーンのファイル(エディタが書く)とは別に、プレイヤーの進み具合と設定をゲームが書く仕組み。

| ID | 内容 |
| --- | --- |
| SV-1 | **保存先の窓口**: platform に「ユーザーのデータのフォルダ」(SDL の `SDL_GetPrefPath` を窓口の後ろに)と、壊れにくい書き方(一時ファイル → 置き換え。今の `WriteTextFile` と同じ)。ファイルは JSON(今の `JsonFormat`) |
| SV-2 | **セーブデータの型**: リフレクションのある構造体・Object をそのまま書く(`ObjectSerializer`)。版の番号と、古い版を読むときの決まり(知らないプロパティは無視、足りないものは既定値。今のシーンの読み方と同じ) |
| SV-3 | **設定**: 音量(全体・種類)、画面(ウィンドウ / フルスクリーン、解像度)、キーの割り当て(IN-3)。起動時に読み、変えたら書く。サンプルにタイトルの「設定」画面とハイスコアの保存 |

## P3 描画の土台

今の描画: スプライトのまとめ描き(`SpriteBatch`)だけ。描く順は「ワールドの一覧の順」、パイプラインは 1 つ、深度バッファ無し、描く先は画面だけ、シェーダは HLSL を dxc で DXIL と SPIR-V にしてヘッダーに埋める(Metal は無い)。

決めること: 2D の描く順の決め方(Unity の Sorting Layer + Order in Layer の形でよいか)、シェーダを後から足す形(ビルド時に変換し続けるか、★ SDL_shadercross などで実行時に変換するか)、色の扱い(リニアと sRGB)。

| ID | 内容 |
| --- | --- |
| R-1 | **2D の描く順**: `SpriteComponent` に `sortingLayer`(名前の表)と `orderInLayer`。描く前に並べ替える(同じなら一覧の順。並べ替えは確保しない)。今は「後から置いたものが手前」なので、シーンを読み替えると前後が変わる問題もこれで直る |
| R-2 | **色の扱い**: 描く先を sRGB にし、計算はリニアで行うか決めて統一(今のうちに直すほど安い。3D のライティングの前提) |
| R-3 | **描く先のテクスチャ(オフスクリーン)**: `RenderDevice::CreateRenderTarget(幅, 高さ)` と、そこへ描いてから画面に貼る流れ。エディタのシーンビュー / ゲームビュー(P4)とポストエフェクト(P6)の前提 |
| R-4 | **深度バッファ**: 描く先に深度を付け、手前・奥を GPU に決めさせる(2D でも z で並べられる。3D の前提) |
| R-5 | **パイプラインとシェーダのアセット**: 混ぜ方(不透明・半透明・加算)、深度の読み書き、カリングを持つ「パイプラインの設定」。シェーダをファイル(.hlsl + .meta)にしてアセットとして読む。ビルド時の変換を続けるなら CMake で assets のシェーダも変換する |
| R-6 | **マテリアル**: 「シェーダ + 値(色、テクスチャ、数値)」のアセット(.material、ScriptableData に近い形)。`SpriteComponent` がマテリアルを指せるようにする(既定は今のスプライトのシェーダ) |
| R-7 | **定数の受け渡し**: フレーム・カメラ・オブジェクトごとの値をまとめて GPU に送る仕組み(今は行列 1 つ)。インスタンス描画(同じ絵をたくさん) |
| R-8 | 2D の小物: タイルマップ(2D のゲームで多く要る)、9 スライス(UI の枠)、線と図形のデバッグ描画(今はスプライトで線を描いている) |

## P4 エディタの強化

今のエディタ: ImGui の窓(Debug、Scene、Inspector、Assets、Log)をゲームの画面に重ねる。シーンビューはゲームの画面そのものをエディタのカメラで映す。

決めること: ★ ImGui の docking 版(別の枝)に替えるか、エディタを別のプロセスにする計画(設計メモ「UIとツール」。Avalonia など)をいつ始めるか、AI から使う口(MCP)をいつ作るか。

| ID | 内容 |
| --- | --- |
| ED-1 | **ドッキングとレイアウトの保存**(★ ImGui docking)。窓を並べて、閉じても配置を覚える |
| ED-2 | **シーンビューとゲームビューを別の窓に**(R-3 の描く先を ImGui の画像として出す)。編集中もゲームのカメラの見え方を確かめられる。解像度の切り替え(16:9、スマホ縦など) |
| ED-3 | **選択の強化**: 複数選択、矩形選択、複製(Ctrl+D)、コピー・貼り付け(コマンドで、Undo できる)、親子ごとの削除の確認 |
| ED-4 | **アセットの操作**: アセットの窓からシーンへドラッグして置く(プレハブ・スプライト)、サムネイル、名前の変更・移動(.meta ごと。参照は GUID なので切れない)、参照元の検索 |
| ED-5 | **シーンの窓の仕上げ**: シーンの見出しをドラッグ先にしてアクターを別のシーンへ移す(`actor.moveToScene`)、シーンを開け閉め、保存していない印(*)、閉じるときの保存の確認 |
| ED-6 | **プロファイラの強化**: フレーム時間のグラフ、区間の木、Chrome Trace(Perfetto)への書き出し。★ Tracy は相談 |
| ED-7 | **エディタを外から操作する口**: 動いているエディタにコマンドを送るソケット(JSON)と、その上の MCP(AI から使う)。CLI と同じコマンドの一覧をそのまま出す |
| ED-8 | (後で)エディタを別のプロセスにする。今のコマンドの層・ED-7 の口の上に作る |

## P5 3D の基礎

ここから 3D。2D と同じワールド・アクター・コンポーネントの上に足す(2D を消さない)。

決めること(段の最初に相談):
- **回転の持ち方**: 今の `Transform::rotation` は z 軸まわりの角度(float)。3D ではクォータニオン(保存とインスペクタはオイラー角で見せる)にするのが一般的。2D はそのまま z 角度で使える形にするか、全部をクォータニオンにするか。古いファイルの読み替えも決める
- ★ メッシュの形式: glTF 2.0(cgltf など。FBX は重い)
- 座標系: 右手系・y が上(今の 2D と同じ y 上)、前は -z か +z か
- 3D と 2D のカメラの使い分け(1 つのシーンに両方あるとき)

| ID | 内容(目安) |
| --- | --- |
| 3D-1 | Transform を 3D に(回転をクォータニオン、`MakeModelMatrix` は 3D の回転、親子の計算、保存の形と読み替え、インスペクタはオイラー角) |
| 3D-2 | 透視投影のカメラ(`CameraComponent` に投影の種類・画角・near / far)、ビューの計算 |
| 3D-3 | メッシュのアセット(★ glTF を読み、頂点・インデックスを GPU に。`MeshAsset`。AssetKind を1つ足す) |
| 3D-4 | `MeshRendererComponent`(メッシュ + マテリアル)、深度ありの描画、カメラから見えないものを省く(視錐台カリング) |
| 3D-5 | 3D のシーンビュー: 飛ぶカメラ(右ドラッグ + WASD)、3D のギズモ(移動・回転・拡大縮小)、クリックで選ぶ(レイと当たり) |
| 3D-6 | プレハブに 3D のモデル(glTF のノードの木をアクターの木として取り込む) |
| 3D-7 | 3D のサンプル(床と箱とプレイヤー。カメラが追う) |

## P6 ライティングとシェーディング

決めること: フォワード(+)かディファード、影の方式、HDR の形式。

- ライトのコンポーネント(平行光・点光源・スポット)、ライトの数の決まり
- PBR のマテリアル(金属・粗さ、法線マップ。★ 接線の計算に MikkTSpace)
- 影(平行光のカスケードシャドウ、点光源の影は後)
- 空(スカイボックス)と環境光(IBL: 空から拡散・反射を作る)
- HDR の描く先とトーンマッピング、露出
- ポストエフェクト: ブルーム、アンチエイリアス(FXAA → TAA)、SSAO、色調補正
- 2D のライト(スプライトを照らす。2D の見た目を上げたいとき)
- シェーダのホットリロード(ゲームを動かしたままシェーダを直す)

## P11 ゲームの仕組み

- **スクリプト言語**(設計メモで保留)。★ C#(.NET のホスト)か Lua などを相談。リフレクション・ハンドル・ログの窓口はスクリプトから使える形にしてある
- タイマー・コルーチンにあたるもの(「2 秒後に」をコンポーネントで簡単に書く)
- ゲーム全体のイベントの受け渡し(シーンをまたぐ通知。ワールド単位のシングルトンの話の続き)
- AI: ★ ナビメッシュ(Recast/Detour)、状態機械・ビヘイビアツリー
- 文言の翻訳(言語ごとの文字の表と、UI の文字を ID で指す)
- (後で)カットシーン・タイムライン

## P12 製品化と性能

- アセットの焼き込み(ネイティブコンバート。設計メモで保留): テクスチャの圧縮(★ BC7 など)、メッシュの最適化(★ meshoptimizer)、ローダの2段目(Cook)をここで使う
- パッケージ(アセットを1つのファイルにまとめる)、製品のビルドの手順
- 非同期の読み込みとストリーミング(大きなワールド)、LOD
- スレッド: 描画のスレッドを分ける、アニメーション・カリングをジョブで
- 大量のオブジェクト(設計メモで保留の `Pool<T>` / ECS)、GC の増分化
- GPU の時間の計測、メモリの予算
